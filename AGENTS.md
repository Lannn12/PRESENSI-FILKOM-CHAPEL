# AGENTS.md

## Cursor Cloud specific instructions

### Overview

**Presensi FILKOM** is a Next.js 16 attendance management system for university events (Chapel, Faculty Day, Sabbath). It uses Supabase (PostgreSQL + Auth) as the backend.

### Services

| Service | How to run | Notes |
|---|---|---|
| Next.js dev server | `npm run dev` | Runs on port 3000; hot-reloads on file changes |
| Local Supabase | `sudo env "PATH=$PATH" npx supabase start` | Requires Docker; runs PostgreSQL on port 54322, API on 54321 |

### Local Supabase setup

The app requires a Supabase instance. For local development without external credentials:

1. Docker must be running (`sudo dockerd` if not started).
2. Run `sudo env "PATH=$PATH" npx supabase start` from the repo root (needs the `supabase/config.toml` generated by `npx supabase init`).
3. Get credentials: `sudo env "PATH=$PATH" npx supabase status -o env` — use `ANON_KEY` as `NEXT_PUBLIC_SUPABASE_ANON_KEY` and `SERVICE_ROLE_KEY` as `SUPABASE_SERVICE_ROLE_KEY`, with `API_URL` as `NEXT_PUBLIC_SUPABASE_URL`.
4. Apply the schema: `PGPASSWORD=postgres psql -h 127.0.0.1 -p 54322 -U postgres -d postgres -f supabase/schema.sql`.
5. Create a test user via the Admin API: `curl -X POST 'http://127.0.0.1:54321/auth/v1/admin/users' -H 'Authorization: Bearer <SERVICE_ROLE_KEY>' -H 'apikey: <ANON_KEY>' -H 'Content-Type: application/json' -d '{"email":"admin@test.com","password":"password123","email_confirm":true}'`.

### Environment variables

Set in `.env.local` (gitignored):

- `NEXT_PUBLIC_SUPABASE_URL` — Supabase API URL
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` — Supabase anon/publishable JWT key
- `SUPABASE_SERVICE_ROLE_KEY` — Supabase service role JWT key

### Commands

See `package.json` scripts: `npm run dev`, `npm run build`, `npm run lint`, `npm start`.

### Gotchas

- `npm run lint` has pre-existing errors (React purity rules, unused vars). These are in the existing codebase and not blocking for development.
- `sudo env "PATH=$PATH"` is required when running `npx supabase` with sudo because nvm's Node.js is not on root's PATH.
- The `supabase/config.toml` is generated by `npx supabase init --force` and must exist before `supabase start`.
- The database schema at `supabase/schema.sql` must be applied manually after starting the local Supabase; it is not wired into Supabase migrations.
